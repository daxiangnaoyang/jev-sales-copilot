# 聊天应用与模型服务使用 / 开发说明

## 使用桌面版微信功能

1. 在 macOS 打开微信并登录，再启动 Jev 销售副驾。
2. 如系统询问，允许应用进行屏幕录制；若系统设置未出现提示，可在“系统设置 → 隐私与安全性 → 屏幕录制”中开启。
3. 将微信切到前台后，应用定位当前对话并刷新预览；不会自动导入客户列表。若需要导入名称，手动点击“导入会话列表”，最多处理当前可见区域的 10 个候选。客户管理支持切换、手动新增和逐项移除。
4. 当前对话预览显示窗口锚点、识别标题、逐条可见消息、发言方向和 OCR 置信度。核对客户归属后点击“确认对象并载入”，文本才会进入草稿；标题 OCR 置信度只表示文字识别把握，不代表客户身份已验证。方向不确定的文字不会作为客户原话送入判断模型。生成前检查和编辑草稿，也可直接粘贴聊天记录。
5. 生成候选回复后，可复制或回填到微信输入框。回填需要在“系统设置 → 隐私与安全性 → 辅助功能”中允许 Jev 销售副驾访问微信。发送仍由用户在微信中完成。

窗口截图与 OCR 在本机进行。当前微信对话在微信前台时自动锚定并显示预览；客户列表导入必须由用户手动触发，且仅读取当前可见名称、最多 10 个候选。群聊过滤依赖名称 OCR 中可见的群标记，不能保证所有结果均为单聊，用户须核对。OCR 识别出的聊天正文不会自动绑定客户或载入草稿；用户确认对象后才进入草稿，生成策略仍需用户手动触发。微信不在前台时不采集，也不会自动发送消息。权限或识别不可用时，可以手动粘贴和复制。

读取窗口需要屏幕录制权限；回填需要辅助功能权限。仓库默认临时签名构建可能无法跨构建复用 macOS 隐私授权。持续进行真实 OCR 验收时，使用稳定签名身份重新构建并授权；参见 [Tauri macOS 签名说明](https://v2.tauri.app/distribute/sign/macos/)与 [Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)。

浏览器模式提供通用屏幕 OCR：点击“读取当前聊天”或“读取可见名单”，在浏览器共享选择器中选择企业微信或其他聊天 App，再框选区域。每次只截取一帧并在浏览器本机运行 OCR；首次需下载并缓存 Tesseract.js 中文模型，截图不上传。读取聊天时需把会话标题和消息区一起框选；标题只在唯一精确匹配客户时自动选中，未匹配不会沿用旧客户，可核对后新建或手动选择。聊天文本和发言方可逐项修改；名单候选最多添加 10 个，不自动滚动或切换外部 App。网页路径复用“用户选择窗口 → 本机 OCR → 人工校对”的通用接入模式；当前并没有企业微信原生适配器，也不等于企业微信官方会话内容存档 API。

## 配置 Bocha Jev

从左侧栏底部或窄窗口顶栏打开“模型与服务配置”；编辑后点击对话框底部“确认并应用模型与 API 接口设置”。客户判断使用固定服务：

- 模型：`bocha-jev-v1`
- 决策接口：`https://jev.bocha.cn/v1/systemone`
- 模型目录检查：`https://jev.bocha.cn/v1/models`

在设置中输入 Bocha Jev Client API Key，或在启动应用的环境中设置 `BOCHA_JEV_API_KEY`。兼容读取 `BOCHA_SEARCH_API_KEY`。密钥仅保留在应用本次运行内存。

选择“测试 Bocha Jev 连接”会读取模型目录，不提交客户内容。勾选授权后，点击“生成策略”才会将最近最多 6 条、总长不超过 300 字符的对话发送到 Bocha Jev。账号可用额度和收费以 Bocha 当前账户页面为准。

## 配置 Agent

Agent 负责根据客户判断生成下一步策略和候选回复。服务选择如下：

- **本机 Demo**：演示策略，不请求外部模型。
- **本机 Ollama**：填写本机服务地址与已安装的模型 ID；API Key 可留空。
- **OpenRouter 免费路由**：填写 OpenRouter API Key，模型使用 `openrouter/free` 路由。
- **OpenAI API**：填写 API Key 和模型 ID。
- **自定义 OpenAI-compatible**：填写 HTTPS Base URL、API Key 和模型 ID；本机回环地址允许 HTTP。

输入模型 ID 后可以测试连接读取模型目录，并从可用 ID 中选择。Agent 服务类型、Base URL 和模型 ID 保存在本机；API Key 不保存，关闭应用后需要重新输入。云端 Agent 需要单独勾选数据授权；该授权只对本次应用运行有效。网页模式会从浏览器直接请求配置的 Agent 服务，需目标服务允许 CORS；连接失败可改在桌面 App 使用。

Agent 连接检查只读取 `/models`，不提交聊天内容、不生成内容。运行策略时，Agent 最多接收 12,000 字符的对话文本及结构化判断；云端服务的费用按服务商账户和模型用量计算。

## 配置视频生成 API

在同一设置页的“视频生成模型”中选择“火山方舟 · Seedance 2.5”，填写 API Key 与模型 ID，并点击“测试视频 API 连接”。连通检查只读取模型目录，不创建任务或生成视频。

完成产品事实核对并生成 15 秒分镜后，在“产品素材”页点击“按分镜生成 15 秒视频”。应用会把分镜提示词和已上传产品图发送给 Seedance；创建生成任务可能计费，点击后还会出现二次确认。生成状态会轮询回读，成功后显示视频链接及预览；链接由服务商提供，24 小时有效，请及时保存并人工核对产品形状、字幕、口播和事实。调试时不得调用真实生成接口。

## 开发入口

前端调用和界面位于 `src/App.tsx`；Agent/视频服务偏好存储位于 `src/persistence.ts`。浏览器 Agent 路径为 `src/browser-agent.ts`，视频 API 和分镜转换分别位于 `src/video-provider.ts`、`src/video-storyboard.ts`。Tauri 命令注册在 `src-tauri/src/lib.rs`，macOS 微信采集和桌面 HTTP 请求实现在 `src-tauri/src/macos_wechat.rs`。

主要命令：

- `scan_wechat`：枚举并读取目标微信窗口。
- `import_recent_wechat_customers`：读取会话列表可见区域。
- `bocha_jev_decide` / `check_bocha_jev_provider`：Bocha Jev 判断与连通检查。
- `agent_strategy` / `check_agent_provider`：Agent 生成与模型目录检查。
- `check_seedance_video_provider` / `create_seedance_video_task` / `get_seedance_video_task`：视频服务检查、创建任务与轮询查询。
- `fill_wechat_input`：回填候选文本，不点击发送。

微信 OCR 使用 Core Graphics 查找窗口、`screencapture` 截取指定窗口、Vision 识别；窗口焦点由辅助功能树辅助确认。会话标题 OCR 与正文区域分开处理；消息按左右气泡位置判断发言方向，昵称行挂接到消息，时间分隔、系统提示与不确定方向单独处理。识别后以窗口 ID、会话标题和可见消息组成锚点，载入前再次读取并比对，防止会话切换时沿用旧结果。源代码、配置与构建命令见 [README](../README.md#开发)。
